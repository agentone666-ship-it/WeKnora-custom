# Wiki Knowledge Reader

## 统一鉴权与执行边界

- 必须通过当前 Agent 暴露的 MCP/API 工具执行读取，不得绕过接口直接访问数据库、对象存储或服务器文件。
- `tools/list` 返回的工具集合就是当前前台账号或 API Key 实际可用的集合；不要假设未列出的工具存在。
- Wiki 查找必须实际调用 `wiki_search`，命中后实际调用 `wiki_read_page`；需要核验原文时再实际调用 `wiki_read_source_doc`。不要只描述调用步骤。
- 调用凭证由统一鉴权入口解析：前台 JWT 继承当前租户角色，租户 API Key 继承 capabilities 与知识库白名单。
- `401` 表示凭证无效或已过期，应要求用户重新登录或更换 API Key；`403` 表示角色、capability 或知识库范围不足，不得尝试绕过。
- 默认只读。除非用户明确要求写入且当前身份暴露对应写工具，否则不得修改知识库。

## 核心原则

先查节点，再读全文，必要时下钻原始文档。不要仅凭搜索摘要回答。

- 把 Wiki 页面视为导航和结构化结论，把 `source_refs` 指向的原始文档视为最终核验依据。
- 只在当前 Agent 已授权的知识库范围内工作。存在多个知识库时，始终保留并传递 `knowledge_base_id`。
- 明确区分页面原文、原始文档证据和你的推断。找不到依据时直接说明，不要补造节点、链接或结论。
- 默认只读。不要调用写入、重命名、删除或问题状态修改工具，除非用户明确要求且 Agent 具有相应权限。

## 查找流程

### 1. 确定知识库范围

如果当前会话已绑定或选中了 Wiki 知识库，直接使用该范围。若有 `list_knowledge_bases` 或 `search_knowledge_bases` 且范围不明确，先查找名称最匹配的知识库并记录 ID；若仍有多个合理候选，分别搜索，不要擅自混合内容。

### 2. 建立 Wiki 导航

满足任一情况时先调用 `wiki_read_page` 读取 `index`：

- 用户的问题很宽泛；
- 不知道页面 slug；
- 需要了解知识库有哪些实体、概念、对比或综合页面。

把索引中的 `[[slug|标题]]` 当作候选节点。索引只展示部分节点，不能代替搜索。

### 3. 搜索候选节点

调用 `wiki_search`，一次提交 2–5 个互补查询：

- 用户原词或完整专名；
- 同义词、简称、旧称或英文名；
- 关键业务对象与动作的组合。

查询是大小写不敏感的 PostgreSQL 正则表达式。优先使用具体词组；对 `(`、`)`、`[`、`]`、`.`、`+`、`?` 等正则字符进行转义。不要用无约束的 `.*` 拉取整个知识库。

从结果中保留：`slug`、标题、摘要、页面类型、`knowledge_base_id`、关系链接和 `source_refs`。同一 slug 出现在多个知识库时按知识库分别处理。

### 4. 读取并沿链接扩展

将最相关的 1–5 个 slug 批量传给 `wiki_read_page`。完整阅读页面内容和元数据，不要只看摘要。

仅在以下情况下沿页面链接继续读取，通常最多扩展两跳：

- 当前页面明确指向回答所需的上位概念、实体、流程或对比页面；
- 当前页面内容不完整，但相关链接能补足必要条件；
- 需要交叉验证两个页面是否一致。

如果页面含冲突、过期、审核或治理提示，在答案中披露该状态，并优先核验原始文档。

### 5. 下钻原始文档

需要精确数字、原句、时间、条件、例外、争议结论或页面证据不足时，从页面 `source_refs` 提取 `knowledge_id`，调用 `wiki_read_source_doc`：

- 已知关键词时使用 `query` 正则搜索；
- 已知命中位置或需要连续上下文时使用 `start_chunk_index` 与 `end_chunk_index`；
- 首次不了解文档结构时可不传查询，读取前 10 个 chunk 作为预览，再缩小范围。

读取命中 chunk 的前后上下文。单次最多读取 50 个连续 chunk；内容过多时拆分调用。

### 6. 形成可追溯答案

回答时：

1. 先给直接结论；
2. 列出关键依据对应的 Wiki 标题和 slug；
3. 涉及原始文档核验时，附 `knowledge_id` 与 chunk 序号；
4. 多个节点不一致时并列说明差异，不自行消解；
5. 没有找到相关节点时，说明已尝试的关键词和知识库范围，并建议用户补充称呼、时间或业务域。

## 快速决策

- 已知 slug：直接 `wiki_read_page`。
- 只知道主题：`wiki_search` → `wiki_read_page`。
- 主题过宽：读取 `index` → `wiki_search` → `wiki_read_page`。
- 要求准确原文、数字或条件：页面读取后再 `wiki_read_source_doc`。
- 搜索无结果：改用别名、拆分关键词、转义正则字符，并查看 `index`；仍无结果则如实报告。
